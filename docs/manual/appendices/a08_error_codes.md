@page manual_error_codes A8 — Error and Warning Codes

## What you'll do

Look up a numbered message that a run produced, and find out which of the
two numbering systems SWMMVis shows you it belongs to.

A failed run is reported in the simulation status panel as
`ERROR [n] ERROR mmm: …` — the bracketed `n` is an **API error code** and
the `mmm` inside the message is an **engine error**. They are different
catalogues; both are below.

## Where to find it

**Message Logs** panel, the simulation status panel while a run is active,
and the `.rpt` status report opened from **Analysis → Report**. See
\ref manual_running and \ref manual_tabular_results.

For what to *do* about the common ones, see \ref manual_troubleshooting,
which carries remediation advice for the messages users actually hit. This
appendix is the complete index, not a troubleshooting guide.

## Tips and gotchas

- **Two numbers, two catalogues.** `ERROR [1] ERROR 141: …` is API error 1
  reporting engine error 141. Look up the inner number first — it is the one
  that names the object and the cause.
- **`%s` is a placeholder.** The engine substitutes the offending object's
  ID, so the message you see names the junction, conduit or subcatchment.
- **A warning is not a failure, but it may have changed your model.**
  Several warnings report that the engine substituted a value for one it
  could not use.
- **A code missing here means the page is stale**, not that the code is
  invalid. Regenerate with `scripts/gen_error_catalogue.py`.
