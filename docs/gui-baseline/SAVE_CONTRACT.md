# Save ownership and commit contract

Decision for W1/R3: adopt the approved plan's **stage generation, commit on Save** direction. This is an implementation decision within the user's phased authorization. Mesh generation must update the owning project's working state and preview without changing the last saved model. Close → Don't Save must preserve the last saved model and referenced mesh. An additional “Write mesh” command is not needed for the first implementation.

This document specifies the target and records incremental checkpoints. Phases 18–20 provide staged built-in Save, rollback/recovery and prepared-project validation. Phase 22 holds generated INP/2DM changes in memory until Save; Phase 23 stages burned raster/report products under shared job ownership. Import staging, crash-orphan cleanup and complete remapping remain open. Phase 08 now rejects missing/unreadable/empty external snapshots, propagates mesh restore/attribute/BC/reference failures and preserves dirty state and Save As identity. Individual mesh writes are checked; the engine may still have changed files before a later failure. Phase 09 stops before serialization when a mesh synchronization API rejects an edit, preserving dirty state and Save As identity; earlier in-memory setters may already have run. Phase 10 resolves one active mesh, rejects inactive pending edits/ambiguous ownership before mutation, and temporarily requests inline engine output for a selected mesh during built-in INP Save. This prevents engine writes to stale/rebased external paths; the GUI used checked snapshot/patch steps until Phase 15 consolidated mesh publication. Phase 11 explicitly patches the GUI-owned inline mesh payload on every built-in INP Save, including clean repeats, and preserves/overrides unit metadata to match the supplied coordinates. At the Phase 11 checkpoint, transactional rollback and generation staging were still unimplemented; later checkpoints below supersede that limitation.

Phase 12 adds read-only selected-mesh validation before any engine synchronization or file writes. Geometry, finite hydraulic values, coupling ranges/references and active boundary fields are checked even for clean layers; errors identify a one-based item and retain edits for correction/retry. Unset roughness/depth, signed boundary heads/flows and elongated rectangles retain their existing meaning. It does not certify manifold topology, referenced node/series existence, infiltration/groundwater/transport parameters, serialization precision, or engine mesh identity. See the [Phase 12 evidence](../../workplans/artifacts/phase_12_mesh_save_validation/README.md).

Phase 13 checks known built-in Save file identities before synchronization. Model/settings/selected external mesh outputs cannot alias each other, mesh/settings writes cannot replace the source model, model/mesh writes cannot replace source settings, and model/settings outputs cannot replace inactive external meshes. Existing hard links, file/directory symlinks and canonical destinations are checked. Clean views of the selected mesh still follow active ownership; ordinary same-role Save and identical basenames in different directories remain allowed. This is not a full output/resource manifest or protection against concurrent filesystem changes; transaction publication must recheck identities. See the [Phase 13 evidence](../../workplans/artifacts/phase_13_save_path_ownership/README.md).

Phase 14 preserves finite mesh doubles through initial serialization and attribute/BC patches using 17 significant digits. Coordinates/elevations, cell hydraulic values, vertex/cell coupling, infiltration parameters/intervals and numeric boundary/conveyance values no longer suffer the writer's fixed-decimal rounding. Fractional infiltration intervals are retained. Canonical file text intentionally changes; repeated new-format writes remain stable. This does not change UI display precision, recover values already rounded in old files, or repair the engine's other model serializers. See the [Phase 14 evidence](../../workplans/artifacts/phase_14_mesh_numeric_precision/README.md).

Phase 15 combines the selected mesh's attributes and boundary/conveyance sections into one checked read/atomic write, for external and inline built-in INP Save. External Save no longer restores an unchanged snapshot or commits attributes separately before boundaries. A reproduced late boundary short write now leaves the external mesh byte-for-byte unchanged, retains dirty state/identity, and supports repair/retry. External preflight still checks readability before engine serialization. This single-file guarantee does not undo the engine's earlier main-model write or a committed mesh if later reference/settings publication fails. See the [Phase 15 evidence](../../workplans/artifacts/phase_15_combined_mesh_write/README.md).

Phase 16 adds checked engine publication for individual INP and mesh files. A sibling temporary receives serialization; stream errors, flush, sync and close are checked before replacement. Sidecar failures propagate as writer errors, and the GUI surfaces engine diagnostics while retaining pending state and Save As identity. This closes the detected engine short-write false success, not the coordinated multi-file transaction. See [Phase 16](PHASE16_CHECKED_ENGINE_WRITER.md).

Phase 17 checks rendered and copied process-component configurations with the same individual-file publication contract. A failed write/copy now fails the engine Save instead of warning and proceeding; a rendered write never falls back to stale source data after failure. Absolute configuration references write to the destination the emitted reference actually resolves to. Earlier successfully published companions still require coordinated rollback. See [Phase 17](PHASE17_CHECKED_COMPONENT_WRITER.md).

Phase 18 routes built-in GUI Save through an explicit output manifest and staging files. The new engine staging C API redirects physical model, mesh and component writes while retaining final-path reference anchors. GUI mesh patches and project settings also finish in staging before publication starts. Detected preparation failures leave final files unchanged; known role aliases and protected-input conflicts are checked, including discovered component outputs. Resource/settings files publish before the main model. Publication is still a sequence of individually checked writes, with no rollback or crash journal. See [Phase 18](PHASE18_CONTROLLED_SAVE_STAGING.md).

Phase 19 adds checked old/new recovery copies, per-model locking, destination fingerprints, coordinated rollback on detected publication failures, and journal recovery before synchronous/asynchronous model opening. Uncommitted saves restore the old set; committed saves retain the verified new set. Unknown outside edits, corrupt backups and invalid journals stop recovery without silently discarding data. This establishes process-interruption recovery, not power-loss durability or application-wide concurrency/worker safety. See [Phase 19](PHASE19_SAVE_ROLLBACK_RECOVERY.md).

Phase 20 adds a disposable engine parse of the prepared built-in save before publication. Mesh/component references are resolved through the output manifest, settings point to the final model, and model/mesh counts are checked. Hard parse/resource failures retain pending state and saved bytes; unrelated incomplete-authoring diagnostics remain draft warnings. Validation excludes external plugin execution and simulation initialization. This is parse/reference/count coherence, not field-by-field equivalence or solver readiness. See [Phase 20](PHASE20_STAGED_VALIDATION.md).

Phase 22 makes generation return an in-memory replacement mesh and its intended destination. The adopted layer remains authoritative across repeated Saves until model reload; Save skips indexed mutation of the old engine mesh and fully serializes the replacement in transaction staging. New external destinations are allowed, references name final paths, and failed Save retains the pending mesh. Unsupported old cell/edge/tag assignments and groundwater quality FILE rows require remapping and block replacement without publishing. Closing/rejecting or changes to the captured project invalidate generation. This guarantee covers saved INP/2DM, not burned rasters/reports or caches. See [Phase 22 generation](PHASE22_GENERATION_STAGING.md) and [Save integration](PHASE22_GENERATED_TOPOLOGY_SAVE.md).

Phase 23 extends the pending generation payload to burned DEM/report products. Shared job ownership retains their physical stages until successful Save or discard; saved destinations are captured before burning and checked again at Save, and sealed payload hashes detect changed pending files. Auxiliary outputs participate in the same publication, rollback and recovery set. Source dependencies, required-absent raster companions and the whole job directory are protected from output aliases. GDAL copy/flush/close and CSV atomic-write results are checked; unsupported companion-dependent output is refused. Ordinary caches remain outside the transaction, burned Stage-B caching is disabled, and crash-orphan cleanup/import staging/full remapping remain open. See [Phase 23](PHASE23_BURN_OUTPUT_STAGING.md).

The multiple-mesh gate remains partly open. Phase 10 synchronizes and cleans only the chosen active mesh; a sole unflagged legacy layer is accepted, while missing/multiple active flags among several layers fail before writes. Clean inactive layers are excluded from synchronization and patches. Inactive pending edits block Save rather than being discarded or marked clean. Selecting a mesh dirties the project; multi-layer saves force the selected layer's attribute push even if its mesh dirty flag is clear. Loaded/generated inline meshes now receive an active flag too.

For built-in INP Save with an identified mesh, Phase 10 temporarily clears the engine's MESH_FILE token while serializing inline, restores the previous token even on writer error, then adopts the chosen absolute external reference (or an empty inline reference) only after the file chain succeeds. Real-engine tests demonstrate no write to the old external file or a same-named mesh in a different Save As directory. This is a bounded use of the existing API, not ENG-5's complete reference-only/staged serializer: it still emits/discards inline mesh text. Phase 15 removes redundant external restore/patch writes (three commits become one); the readability preflight remains a separate read. Phase 13 covers known path aliases, but plugin exports, saves without an attached mesh, full output manifests and crash recovery remain uncertified.

The `.oswp` stores display configuration, not mesh edit payloads. Simultaneously edited inactive meshes still need a coordinated persistence design; the new refusal is a safety guard, not that feature. Phase 11 repairs persistence of changed XY/connectivity when vertex/triangle/quad counts are unchanged: the inline geometry, attributes and boundary data are rebuilt from the layer after engine serialization, including on clean repeated Save. A boundary vector with the wrong length fails before writing. Header normalization preserves UNITS/SOURCE_CRS even when the engine placed them inside a replaced section; inline output uses the layer’s SI-versus-project-unit flag, now propagated by import and generation too. The regression reopens and initializes saved metric, feet and US-project/SI-mesh files to check physical coordinates. This does not replace the engine’s in-memory topology or prove correct remapping of other cell-indexed aquifer/transport/forcing data. Count equality is still not full model compatibility. Engine APIs can accept invalid values (for example non-finite elevations), and count-mismatch fallbacks can skip fields; rejection checks do not certify complete validation or persistence in those paths.

The raw prompt inventory includes file-picker/save prompts outside these critical journeys. W1 must reconcile every output-producing call before declaring application-wide save safety. Hotstart/plugin/driver multi-file behavior remains an explicit audit item, not assumed atomic.

Phase 24 applies the same draft-before-Save contract to standalone native and SMS mesh imports. A checked private snapshot supplies both preview geometry and the first Save template; final files and the editing engine reference remain unchanged during import. Same-folder SMS conversion chooses a separate destination. Native unowned sections survive patching, while known file-bearing directives requiring dependency relocation are refused. Destination consent captures identity/content before queued work, with checks through publication. Untitled Save As binds a unique filename in the chosen project directory. Stale or abandoned jobs release private ownership; repeated Save retains layer topology ownership until reload. See [Phase 24](PHASE24_MESH_IMPORT_STAGING.md) for scope and testing; native acceptance and complete engine/dependency/remapping parity remain open.

## Writer ownership and staging

1. Snapshot project revision, active mesh identity/revision, engine model state, style state and all final output paths. An operation belongs to that project, not whichever window becomes active later.
2. Build an explicit output manifest: model, GUI-owned mesh, project settings, generated model-attached resources, and any engine-owned companion outputs. Existing input datasets/results are references, not implicitly copied outputs.
3. Stage on the destination filesystem. Every writer must support destination redirection or a mode which omits externally owned resources. Do not rely on changing only the main INP filename. ENG-5's preferred addition is reference-only mesh serialization/output redirection; bulk engine topology replacement is deferred unless run consistency proves it necessary.
4. Write the mesh's complete topology and GUI-owned attributes/BCs/couplings/infiltration, then serialize the model referencing the **final** path. Preserve all sections the GUI does not own. Validate the staged model/mesh combination through reopen, including unit conversion and Save As rebasing. Never publish staging paths in the final project.
5. Check byte counts, flush/close and validation results. Surface the resource and recovery action on every error; warnings are not successful persistence. Engine-side failure injection is needed before relying on an engine success return.
6. Use a recovery journal with old/new paths, file identities and progress. Keep rollback copies until the output set is committed. A sequence of atomic renames is not a crash-atomic multi-file transaction. On restart, detect the journal and restore the last complete set or finish a verified commit; never silently combine versions.
7. Only after publication succeeds, adopt Save As identity, clear dirty flags and emit saved notifications. Failed Save keeps working edits and last successful identity, permitting retry. Clean up only outputs owned by the completed/abandoned operation.

## Acceptance matrix for W1

| Test | Required outcome |
|---|---|
| Generate then Don't Save; generated mesh preview remains visible until close | Reopen has the old disk mesh and model; no unrequested file replacement. |
| Cancel generation / close target / change geometry while worker runs | No stale attachment or final-file write; no effect on another project. |
| INP short write, full disk, external-mesh failure, patch failure, `.oswp` failure | Error names failed stage, old project usable, all dirty state retained, retry possible. |
| Interrupt after each publication step | Recovery reconstructs a coherent old or verified new file set. |
| Save As to another directory, external and inline mixed meshes | References resolve after reopen, no stale topology, complete attributes/BC/coupling/infiltration, correct units. |
| Multiple mesh layers and active mesh change | Explicit active mesh controls the model reference; unrelated layers/files preserved. |
| Run after unsaved generation | Explicitly save via the transaction or run an isolated staged model. Never execute stale engine topology or silently overwrite saved files. |
| Explicit exports / hotstarts / plugin output | Correct overwrite scope, checked errors, no accidental project-clean transition. |

Unit tests cover manifest/path/recovery decisions. Integration tests use actual engine serialization and owned files, with byte-level before/after checks and failure injection. Native close/save prompts and crash recovery are separate acceptance evidence.
