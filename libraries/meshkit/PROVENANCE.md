## Authorized release update — 2026-10-29

The rights holder explicitly authorized relicensing all non-third-party MeshKit code, including earlier contributions, and selected Apache 2.0. LICENSE, NOTICE and RELICENSING.md record the grant and scope. Source notices now identify Apache-2.0 while retaining existing copyrights; robust predicates are unchanged. No ownership conclusion is drawn from Git author metadata. Earlier GPL grants remain available for those revisions.

The standard C++ package links system C++/thread runtimes and public-domain predicates. Its Python extension dynamically links system runtimes and loads into CPython; it does not bundle Qt, GDAL, NumPy, Python or OpenSWMM. The optional Qt targets require Qt Core/Gui/Concurrent with Qt's own terms. Actual local package dependency and license checks are recorded in VALIDATION.md and the completion evidence folder.

## Boundaries not moved

GDAL terrain providers and boundary conditioning, corridor/project capture, engine synchronization, feature exports, project mesh adoption/undo and save orchestration remain application adapters. `model_qt` retains the existing shared infiltration metadata and serialization helpers; separating generic arrays from application-specific attributes is still required for the final Qt-free interface.


## Shared numerical implementations

The native CDT template continues the historical kernel listed above. Joint mapped planning, patch generation/validation, automatic blocks, size fields, source simplification and independent audits now also reside in standard C++ implementations. Qt facades convert small requests and borrow delivered arrays for audits. New generic mixed jobs, raster certificates, streaming codecs and Python bindings are part of the Apache-2.0 project. The native Python/C++ package carries no application-specific infiltration/coupling ownership.
