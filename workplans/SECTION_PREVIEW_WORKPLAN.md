# Section Preview Panels — Workplan (Slice SP)

Status: **DRAFT — awaiting mockup review** (see `workplans/section_preview_examples/`)
Author: prepared for review 2026-08-14

Adds live, engine-accurate vector section/profile diagrams with dimension leader
lines to three surfaces:

1. **Properties panel** — a resizable preview panel at the top of the property
   grid that opens when a link or node is selected (conduit: Section ⇄ Profile
   toggle; node: profile + plan inset of connecting pipes).
2. **Cross-section editor** (`LinkCompoundEditDialog` XSection page) — replaces
   the static-SVG-icon-only experience with a high-fidelity live preview driven
   by the engine `swmm_xsect_*` API. This realizes the previously referenced but
   missing "Slice BN Phase 6.4.4 §S.11" plan (cited in `linkcompoundeditdialog.h`).
3. **LID control editor** (`LidControlEditorDialog`) — per-type layer-stack
   diagram that tracks the active tab and current values.

Review mockups: `workplans/section_preview_examples/*.svg|png` (generated by
`gen_section_preview_examples.py` in the same folder).

---

## 1. Key findings the plan is built on

- **Engine geometry API exists and is unused by the GUI.** The bundled
  `libopenswmm.engine` exports an opaque xsect handle API:
  `swmm_xsect_create / _free / _width_of_depth[_array] / _area_of_depth /
  _hydrad_of_depth / _critical_depth / _full_properties / _is_open /
  _shape_name`, plus `_create_irregular / _create_custom / _create_street`.
  Sampling `width_of_depth` over N depths gives an exact outline polygon for
  all 26 shapes — no pregenerated assets needed.
  - *Prerequisite check:* the GUI currently includes only
    `openswmm/engine/openswmm_links.h`. Confirm `openswmm_xsect.h` is present
    in `OPENSWMMENGINE_INSTALL_DIR` and add it to the imported target usage.
- **⚠ Two shape-numbering spaces.** `SWMM_XSECT_*` in `openswmm_links.h`
  (used by `xsectshapegeom.h`) differs from the engine xsect-module codes
  (e.g. `SWMM_XSECT_MOD_BASKET = 10` vs xsect `modbaskethandle = 8`). All new
  code must convert through one named mapping function — never literals.
- **Existing patterns to follow:** `StreetSectionPreview`
  (`streeteditordialog.h/.cpp`) for a provider-driven QPainter section widget;
  `StylePreviewSwatch` for the live-preview idiom; `QSplitter` +
  `setObjectName()` + `DialogLayoutWatcher` for resizable, persisted panes;
  `swmvis_test::assertDialogA11y` for the a11y contract.
- **Properties panel insertion point:** `PropertiesPanel::setupUi()`
  (`src/ui/panels/propertiespanel.cpp:230-293`) — vertical layout: layer combo
  row, open-editor button, stats row, `m_treeView`. The preview slots between
  the header rows and the tree via a vertical `QSplitter`.
- **Live update hook:** adapters already emit `changed()`
  (cf. `applyGeomRowFlags` lambda, propertiespanel.cpp:779-791). The preview
  subscribes to the same signal, so grid edits, dialog edits, and the attribute
  table stay synchronized through the adapters (MVC per CLAUDE.md §5.1 — no new
  data stores).
- **LID constraint:** the engine has LID layer setters but no getters
  (`lidcontrolprovider.h`), so the LID diagram is driven from the GUI-side
  `LidControlProvider` cache and shows placeholders for models loaded from file
  until values are (re)entered.
- **Shape metadata:** `include/ui/properties/xsectshapegeom.h` is the single
  source of truth for shape names + geom labels/applicability. It currently
  surfaces 21 of 26 shapes (missing: BASKETHANDLE, SEMICIRCULAR, CUSTOM,
  FORCE_MAIN, DUMMY).

## 2. Architecture

New module `include/ui/sectionview/` + `src/ui/sectionview/` (Qt Widgets, no QML):

```
XsectSampler            RAII wrapper over swmm_xsect_* (create from shape +
                        geom1..4; outline polygon via width_of_depth_array;
                        full properties). Owns links.h ⇄ xsect-code mapping.
SectionDiagramScene     Renderer-agnostic paint routines (QPainter): closed
                        section fill/outline, ground hatch, structure walls,
                        vdim/hdim dimension lines with arrowheads, leader
                        lines with elbow + landing text, plan-inset compass.
                        Colors from QPalette + theme roles (dark-mode safe).
SectionPreviewWidget    QWidget host: paints a SectionDiagramModel, handles
                        DPR, resize, elision/decluttering of labels at small
                        sizes, "No selection" empty state.
Builders (model layer)  ConduitSectionModelBuilder / ConduitProfileModelBuilder /
                        NodeProfileModelBuilder / LidLayerModelBuilder —
                        pure functions: adapter/provider + engine → plain
                        SectionDiagramModel struct (testable headlessly).
XsectIconEngine         Renders shape-list icons (and any toolbar uses) from
                        XsectSampler outlines; replaces the 26 static SVGs;
                        follows iconfactory.cpp theming/caching approach.
```

View = `SectionPreviewWidget`; model = `SectionDiagramModel` built from the
existing adapters/providers; controller = the hosting panel/dialog wiring
signals. One widget, three hosts.

## 3. Surface designs (per mockups)

### 3.1 Properties panel preview (mockups 1–3)

- Wrap preview + `m_treeView` in `QSplitter(Qt::Vertical)`,
  `objectName "propertiesPreviewSplitter"`, `setChildrenCollapsible(false)`;
  sizes persisted by `DialogLayoutWatcher` naming contract.
- Collapsible via a small header toggle button (adds the first
  expander-style control to the codebase; keep it minimal — a checkable
  QToolButton). Hidden entirely for object kinds with no diagram.
- **Conduit:** Section ⇄ Profile toggle (mockups 1, 2).
  - Section: outline from `XsectSampler`, wall band, centerlines, D/height
    dimension, invert/crown elevation leaders, footer with A/Rh/Wmax/barrels.
  - Profile: both end nodes (rim/invert), ground hatch, sloping pipe with
    crown line, inlet/outlet offset dimensions, L and S along the pipe axis.
  - IRREGULAR/STREET/CUSTOM: outline from transect/street/curve tables
    (`_create_irregular/_street/_custom`); DUMMY: "no cross-section" state.
- **Node (junction/outfall/divider/storage):** profile with rim/invert/max
  depth/surcharge marker and every connecting pipe drawn at its invert offset
  with crown tick + invert label; plan-view compass inset of link headings
  from map coordinates (mockup 3). Storage nodes: chamber silhouette from the
  storage shape/curve (`storageshapegeom.h`) instead of a rectangle.
- Orifice/weir/outlet: Section view of their opening; Profile disabled.

### 3.2 Cross-section editor (mockup 4)

- Right pane of the XSection page gains the live preview above the geom form
  (or as middle pane of the existing `xsectionShapeSplitter`); updates on
  every spin/pick change through the existing `applyXsect()` path.
- Dimensions rendered for the geoms that apply to the shape
  (`xsectGeomApplies`), highlighting the geom currently being edited.
- Property readout box: `swmm_xsect_full_properties` (A, Rh, Wmax, open/closed).
- Replace `makeShapeIcon()` SVG lookup with `XsectIconEngine`; keep
  `makePlaceholderShapeIcon` as final fallback; retire qrc SVG entries once
  parity confirmed.
- Add the 5 missing shapes to `xsectshapegeom.h` (unlocks BASKETHANDLE,
  SEMICIRCULAR, CUSTOM, FORCE_MAIN, DUMMY in list + icons + preview).

### 3.3 LID editor (mockup 5)

- Diagram pane on the right of the existing `QSplitter` (form left, diagram
  right) or above the tab widget — decide during implementation by width.
- Layer stack varies by LID type (surface/pavement/soil/storage/drain/
  drainmat as applicable), e.g. Bio-Retention: surface+soil+storage+drain;
  Permeable Pavement: surface+pavement+soil+storage+drain; Rain Barrel:
  storage+drain only; Green Roof: surface+soil+drainmat; Vegetative Swale:
  surface only. Thickness dimensions to scale, parameter leaders, active-tab
  layer highlighted, runoff-in/underdrain annotations.
- Driven by `LidControlProvider` signals (`paramsChanged`). Values not yet
  entered → hatched "unknown" layer with em-dash labels (readback constraint).
- Follow-up (separate slice, engine API already exists): add Pavement and
  Drainmat tabs so those layers are editable, matching the per-type stacks.

## 5. Risks / open questions

- `openswmm_xsect.h` availability/version in the engine install must be
  confirmed before SP.1 (sibling repo, not vendored here).
- Small-panel legibility: dimension text must declutter (drop leaders before
  dims, dims before footer) below ~260 px width.
- Storage-node silhouettes from functional storage curves may need capping
  for unbounded A(h) — clamp at max depth.
- Plan inset requires link vertex/coordinate access in the properties panel
  context — available via `SWMMModelLayer` spatial queries; confirm cost is
  negligible on selection change.
- Icon replacement changes the qrc; keep SVGs until SP.3 parity sign-off.
